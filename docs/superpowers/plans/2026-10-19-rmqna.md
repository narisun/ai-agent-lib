# rmqna Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new `examples/rmqna` workspace — agent `rmqna` + MCP server `rmqna-data` — where the model writes DuckDB SQL over a copy of the rmprep CSV snapshot, the server validates and executes it, and Phoenix shows the SQL on the tool span.

**Architecture:** CLI-scaffolded workspace, rmprep-style customization: the server replaces its generated sample tools with three tools over an example-local contained DuckDB engine (sqlglot AST validation, read-only single SELECT, table allowlist, row cap, timeout); the agent embeds a schema document rendered from `data_model.csv` plus hand-authored notes, and runs a clarify → resolve → generate → execute → repair(≤2) flow in the prompt over the standard template graph. Library code is untouched.

**Tech Stack:** Python 3.11, agentlib CLI scaffolding, DuckDB (in-memory), sqlglot (dialect `duckdb`), LangGraph via library seams, Phoenix via existing tracing, library `run_eval` for evals.

**Spec:** docs/superpowers/specs/2026-10-19-rmqna-design.md (this worktree; read it first — R-numbers and D-numbers below refer to it).

## Global Constraints

- Library packages (`packages/*`) are not modified by any task; everything lives under `examples/rmqna` plus the two root `pyproject.toml` registration edits in Task 1.
- No new `AC2_*` variables; workspace services use only generated settings. The engine's data directory is a module constant resolved from the service's `ENV_FILE` parent (`../../data`), not configuration.
- `rm_scenarios.csv` must not exist in `examples/rmqna/data/`; `data_model` is never a queryable table; both absent from every tool payload (spec anti-goal).
- Engine limits (spec D3): row cap 200 via AST `LIMIT cap+1`, timeout 30 s with `cursor.interrupt()`, `SET enable_external_access = false` after load, per-call cursor, table-name regex `^[a-z][a-z0-9_]*$`.
- SQL dialect is `duckdb` for both generation and validation (spec D5 trade-off).
- Ports: agent 8200, server 8300. Names: `rmqna`, `rmqna-data` (≤ 28 chars).
- Committed tests: scripted/fake model only, loopback-only sockets, config loaded from `.env.example` via `load_test_config`. Eval tests are `-m eval`, skip on the fake provider (real model only, run on demand).
- Every MCP tool pinned (`agentlib registry pin rmqna-data`) after any tool change; policy rules/samples appended for every new resource.
- Repo gates stay green: workspace `python -m ai_agent_lib_cli check`, root pytest/mypy/ruff/lint-imports, `tests/architecture`.
- mypy strict applies to the new example (root `mypy_path` + the workspace's own config); ruff line-length 100.
- Commit messages follow the repo's voice (`component: what the change makes true`), each ending with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.

## Review Focus

Spec-implied behaviors no generated test covers; each line's pinning test is added to the owning task below.

1. CTEs: `WITH x AS (SELECT …) SELECT … FROM x` must be accepted, and the CTE alias must not be reported as an unknown table (RM-grade SQL uses CTEs constantly) — Task 3.
2. Set operations (`UNION`, `EXCEPT`): refused with a structured error naming the construct, never a crash or silent partial execution — Task 3.
3. A trailing semicolon on a single SELECT is accepted; `SELECT …; DROP TABLE x` and comment-smuggled second statements are refused as multi-statement — Task 3.
4. A model-supplied `LIMIT` larger than the cap is lowered to the cap (+1 detection) while a smaller one is kept; `OFFSET` survives — Task 3.
5. `search_column_values` against a non-text column casts to text rather than erroring (entity resolution over ids/numbers is a real RM case) — Task 3.
