# rmprep tracing with Langfuse

Agent Lab handles chat, agent selection and memo versions. Langfuse shows the
model and MCP work behind each answer. The agent owns its checkpoint database;
Langfuse receives checkpoint IDs so you can connect a trace to saved state.

The [shared library adapter](langfuse.md) uses [Langfuse's OTLP/HTTP interface](https://langfuse.com/integrations/native/opentelemetry).
The existing Python OpenTelemetry packages provide the exporter. The library's
public invocation API is unchanged; rmprep adds optional `output.trace` metadata.

## 1. Start the separate backend

Choose one setup:

- **Restricted desktop:** ask the platform team for an internal Langfuse URL,
  project ID, public key and secret key, then go to step 2. Python and pip are
  sufficient on the developer's machine.
- **Local trial host with Docker installed:** open Command Prompt in this
  separate sibling `langfuse` folder and run:

```bat
start.bat
```

This starts Langfuse web and worker services, PostgreSQL, ClickHouse, Redis and
object storage in a separate Compose project. The web UI is
<http://localhost:3000>. All published ports bind to loopback. Agent Lab still
runs separately at <http://127.0.0.1:8765>.

Sign in as `developer@agentlab.local`. Read `LOGIN_PASSWORD` in
`.env` in the separate `langfuse` folder on your machine. Setup generates the password and keys
once and creates the **rmprep trial** project. Keep this file private. It is
excluded by that folder's `.gitignore`. Langfuse and Agent Lab have separate logins.

```bat
start.bat status
start.bat stop
```

Stopping preserves traces and databases. Restarting reuses the same credentials.
This is a local trial deployment. A shared service needs an HTTPS address,
team authentication, backups and retention managed by its platform owner.
The [official hosting guide](https://langfuse.com/self-hosting) covers deployment
options. On AWS, plan separate web/worker services, managed PostgreSQL, Redis,
S3 and ClickHouse. ClickHouse is still required; the agent checkpoint database
does not replace it. The official AWS Terraform uses EKS; an ECS Fargate rollout
needs its own infrastructure design.

## 2. Configure rmprep

Run the existing Python/pip setup if needed:

```bat
setup-local.bat
```

Local Langfuse setup creates `agent.env` in the separate `langfuse` folder. For a shared service,
create a private environment file containing the settings below and use its path.

| Variable | Purpose | Local trial value |
| --- | --- | --- |
| `EAP_LANGFUSE_ENABLED` | Enable the optional rmprep adapter | `true` |
| `LANGFUSE_BASE_URL` | Langfuse origin | `http://localhost:3000` |
| `LANGFUSE_PROJECT_ID` | Project ID from its browser URL | `rmprep-trial` |
| `LANGFUSE_PUBLIC_KEY` | Project API public key | Generated by setup |
| `LANGFUSE_SECRET_KEY` | Project API secret key; agent process only | Generated by setup |
| `EAP_LANGFUSE_CAPTURE_CONTENT` | Include model messages, tool schemas, tool arguments/results and accepted answer | `false`; set to `true` for this walkthrough using approved test data |
| `EAP_LANGFUSE_ENV_FILE` | Optional separate settings file | Absolute path to `agent.env` |

Process variables override the separate file, which overrides the agent's `.env`.
For the local walkthrough, change `EAP_LANGFUSE_CAPTURE_CONTENT` to `true` in
`agent.env`, then run from the repository root:

```bat
set "EAP_LANGFUSE_ENV_FILE=%CD%\..\langfuse\agent.env"
start-local.bat rmprep
```

Use the existing [Anthropic model setup](local-startup.md) for model credentials.
Langfuse keys are separate from Anthropic keys. The browser receives only the
private trace URL. The agent's JSONL model tracing remains available when
`EAP_MODEL_TRACE_PATH` is configured. Credential masking is best effort;
conversation content and business records remain visible when content is enabled.

You do not need to change `EAP_TELEMETRY` or `OTEL_EXPORTER_OTLP_ENDPOINT`.
This adapter owns a separate trace exporter. Operational metrics keep their
existing destination; they are not sent to Langfuse's trace endpoint.

## 3. Verify a memo and follow-ups

In Agent Lab choose **rmprep** and start a new chat. Send these questions in order:

1. `Prepare a meeting memo for JONE-0022 as of 2026-08-03.`
2. `Which covenants need discussion for this client?`
3. `Summarize the next steps in the memo.`

Each accepted answer shows token usage, cache counts, elapsed time and an
**Open trace in Langfuse** link. Open the link and sign in to Langfuse. Export is
asynchronous, so a new trace may take a few seconds to appear. A link identifies
the intended trace; it is not an ingestion receipt.

Check these relationships:

- Each question has a distinct trace and `request_id`. All three traces share
  a scoped `sessionId`, derived from caller, tenant, agent and thread.
- The root `rmprep.turn` shows the question and accepted answer when content
  capture is enabled. Its duration measures the agent run. Agent Lab's elapsed
  time also includes HTTP transport and UI dispatch.
- Each `model` generation represents one actual provider attempt. Open its
  input to see system instructions, saved conversation, current question and
  tool schemas. Open the next generation after an MCP call to see its result
  included as model input. Prompt instructions stay in the versioned local files.
- Tool observations show the registry's MCP tool name, server and tool-call ID.
  The memo should retrieve `rmprep-data.get_memo_evidence`; a covenant detail
  question may also retrieve `rmprep-data.get_client_records`. A question answered
  from saved evidence may correctly make no new MCP call.
- Generation usage separates uncached input, cache reads, cache writes and
  output. Adding the three input categories gives Agent Lab's input token total.
  Counts are reported by the model provider; absent usage is not invented.
- Root metadata contains checkpoint IDs and parent IDs for exactly that request,
  plus any newly created artifact IDs. Expand Agent Lab's **Turn inspector** to read
  those checkpoints through the authorized agent endpoint. Full checkpoint
  contents are not copied to Langfuse.

Reopen the chat and confirm its trace links remain attached to the original
responses. Opening links or the inspector must not invoke the agent again.

### Verified local run: 13 October 2026

The walkthrough above was run through Agent Lab with Anthropic
`claude-sonnet-4-5` and the separate Langfuse OSS **4.58.0** backend. All three
answers completed in one thread. These are observed results, not fixed expected
token counts or timings for future runs.

| Question | Model calls | MCP calls | Checkpoints | Input / output tokens | Cache read / write tokens | Response time |
| --- | ---: | --- | ---: | ---: | ---: | ---: |
| Prepare the memo | 2 | `get_memo_evidence` | 4 | 29,258 / 2,465 | 3,873 / 25,377 | 48.05 s |
| Discuss covenants | 3 | `get_client_records` | 4 | 26,123 / 1,100 | 16,410 / 9,702 | 27.22 s |
| Summarize next steps | 1 | None; used saved memo | 4 | 29,442 / 774 | 3,516 / 25,923 | 12.27 s |

Verification matched Langfuse observations to both agent and MCP audit records
using `request_id`. Every exported checkpoint reference matched the agent's
database, and each follow-up's checkpoints continued from the preceding turn.
Both follow-up model inputs contained the saved memo. After each MCP call, a
later model input contained the corresponding tool result. The covenant answer
matched the two failing covenant records in the CSV data.

Langfuse generation usage matched Agent Lab's totals, including cache reads and
writes. Reloading the chat preserved all three trace links and response metrics.
The covenant turn's three generations include an output-review retry; they are
three provider attempts, not duplicate callback observations.

For API-based verification on this Langfuse version, use
`GET /api/public/v2/observations` with `traceId` and a bounded time range. Include
the `core,basic,usage,io,metadata,model` field groups. The legacy traces API is
disabled for this v4 installation. Input/output fields in the API response are
JSON-encoded strings; decode them before comparing content. See the
[public API guide](https://langfuse.com/docs/api-and-data-platform/features/public-api).

## Troubleshooting

**No link:** check that the rmprep HTTP service started with the Langfuse settings.
The trial wraps `/invoke`, including its live response mode. The standalone
`rmprep` CLI and legacy `/invoke/stream` step-debugging endpoint keep their existing
behavior. Old answers created before enabling tracing have no trace link.

**Link opens but no trace:** check the Langfuse project, API keys, worker health
and agent exporter logs. The bounded background exporter does not retry the
business request or discard its accepted answer. It can lose diagnostic spans
during a prolonged outage; audit and checkpoints remain the authoritative records.

**Input/output missing:** enable `EAP_LANGFUSE_CAPTURE_CONTENT` and restart
rmprep before a new turn. Previously recorded metadata-only traces stay unchanged.

**Checkpoint references unavailable:** the accepted answer is kept and the root
metadata reports `checkpoints_unavailable`. Use the agent's inspector. Reference
lists are bounded to 64 parent-graph checkpoints, with a truncation flag.
